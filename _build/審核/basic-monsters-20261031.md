# 基本怪物合集包名稱對照（2026-10-31）

PF1 系統 11.11 內建的「基本怪物」（Basic Monsters）合集包，這次補上中文名稱。

- 新檔：`translations/pf1.basic-monsters.json`（繁中）
- 簡體版：`_build/審核/zhcn/pf1.basic-monsters.json`（要給 pf1e-compendium-zhcn 用時，手動複製到它的 `translations/`）
- 產生這兩份的程式：`_build/basic_monsters.py`（譯名與來源都寫在裡面，要改譯名改那支再重跑）
- 分支：`basic-monsters-map`，沒有合進 main、沒升版號、沒發 release

## 一句話

這包只有 **15 隻**（系統開場導覽用的示範怪，不是整本怪物圖鑑）。**補了 13 隻，2 隻沒補**。
只翻怪物名稱和 token 名稱，內文和怪物身上的物品都沒動。

CHM 沒有一隻一隻的怪物頁（只有怪物規則、模板、魔寵這些），所以 CHM 的譯名是從召喚表、魔寵表、專長、物品裡**提到這隻怪的地方**取的。
每一條都對過英文原文確定是同一隻（例如「人類骷髏」那三處的原文都是 human skeleton）。

### 標 ⚠ 的，請你看一眼

都有填，但來源之間寫法不一，挑的理由寫在這裡，不同意就改 `_build/basic_monsters.py` 的那一列：

- **Human Zombie**：CHM 兩種寫法，「人類喪屍」7 處（特殊魔法防具的盾、集團戰鬥的人類喪屍軍隊）、「人類殭屍」1 處（靈器學派的死靈僕從）。CRB 的不死生物通稱也是「喪屍」，舊檔與上游也都是「喪屍」，所以取「人類喪屍」。
- **Wasp Swarm**：CHM 兩種寫法各 2 處，「黃蜂集群」（APG 召喚怪物表、UM 法術）、「黃蜂群」（奇物、遭遇表）。上游是「黃蜂群」，用它當決勝。如果你偏好跟召喚怪物表一致，就改成「黃蜂集群」。
- **Homunculus**：CHM 寫「人造人」，只有進階魔寵索引一處寫「人造人／何蒙庫魯茲」；上游用「何蒙庫魯茲」。照 CHM 優先取「人造人」。
- **Acolyte**：CHM 沒提到這隻 NPC。CHM 裡的「輔祭（Acolyte）」是極限戰役的組織成員，不是同一個東西，沒拿來用；上游寫「侍祭」，跟 CHM 裡「拉茲米爾的侍祭」「次經侍祭」的用字一致。

上游來的 4 條（Acolyte、Battle Mage、Poacher、Street Magician）沒有跟你的用語集對過，用語集如果有定名，以用語集為準。

## 沒補的（留英文）

| 英文 | 狀況 |
|---|---|
| Goblin Alchemist | CHM、上游、舊檔都沒有中文名（上游只翻了牠身上的物品） |
| Human Bandit | 同上。CHM 有「土匪」，但對的是 Bandit 這個字，不是這隻怪，不拿來用 |

**只差用語集就能補的就是這 2 條**，加上 4 條上游來源的要對一下用語集。
用語集在你本機，雲端拿不到，所以沒查。

## 刻意沒做的

- **內文**：CHM 沒有這 15 隻的怪物頁，沒有現成譯文可用。內文維持英文。
- **怪物身上的物品名**：上游有翻，但有錯，例如怪物的 Poison（毒）能力被翻成法術名「毒擊術」，法師學派能力 Enchanting Smile 被翻成「惑控學派」。照「寧可少補也不要補錯」，一條都沒收。
- **八個 pf1-bestiary.* 檔**：照交代沒動。

## 載入會不會壞

- 對照檔**沒寫 mapping**，用 Babele 內建的怪物對應（名稱 → `name`、token 名稱 → `prototypeToken.name`）。這是 Babele 2.9.1 原始碼裡的預設，不會指到不存在的轉換器，也沒動 `scripts/`。
- 舊 bestiary 檔寫的 `token.name` 是 Foundry v9 以前的欄位，新版已經不存在，新檔沒沿用。
- PF1 原始碼裡這 15 隻沒有存 token 名稱，Babele 會跳過那一欄，token 會跟著 Foundry 用怪物名稱（就是翻好的「中文（English）」）。從合集包拖出來的 token 名稱若是「人類骷髏（Human Skeleton）」而不是「人類骷髏」，是正常的。
- 條目清單用程式對過 PF1 v11.11 原始碼（gitlab 的 `v11.11` 標籤，`packs/basic-monsters`），15 條一條不差。
- 雲端這邊沒能在 Babele 裡實際跑一次（環境不允許執行下載來的程式），所以下面的 Foundry 實測一定要做。

## 驗證（verify_compendium.py）

雲端沒有你本機的上游資料夾，改用上游 git 歷史裡檔案集合跟本模組一樣的那一版（`430934d`，2025-02-22「適配 v11.2」）當比對來源。

| 項目 | 改之前（main） | 改之後 |
|---|---|---|
| 檔案集合一致（30 檔） | 過 | **不過：多 1 檔 `pf1.basic-monsters.json`，這是預期的** |
| entries 鍵集合一致 | 過 | 過 |
| mapping 完全未變 | 過 | 過 |
| 結構一致 | 過 | 過 |
| HTML 標籤完好 | 過 | 過 |
| 連結 ID 完好 | 過 | 過 |
| 無殘留簡體 | 不過（12 處） | 不過（同樣 12 處） |

前後一比，唯一的差別就是多出來的那一檔。

「殘留簡體 12 處」是 **main 本來就有、跟這次無關的**：全部是「樑」字（月光橋、可攜式橋、女巫職業說明等）。
雲端裝的 OpenCC 是 1.4.2，這版把「樑」當成要轉成「梁」的字，你本機的舊版不會。換句話說是驗證工具版本不同造成的誤報，不是譯文壞了。
新檔我另外用同一個 OpenCC 掃過，沒有簡體字。

驗證程式只比對來源有的 30 檔，所以新檔本身它不會檢查；新檔的檢查是上面那幾項（條目清單、欄位、殘簡）另外做的。

## 在 Foundry 裡實測

1. 切到這個分支（或把 `translations/pf1.basic-monsters.json` 複製到你 Foundry 的 `Data/modules/pf1e-compendium-zhtw/translations/`）。
2. 重新啟動世界（Babele 只在載入時讀對照檔，重新整理網頁就夠）。
3. 打開 F12 主控台，確認沒有 `pf1e-compendium-zhtw | 向 Babele 註冊失敗` 或 Babele 的紅字錯誤。
4. 合集包分頁裡找「基礎怪物」（PF1 系統那一區）：
   - 合集包標題應該是「基礎怪物」
   - 列表裡 13 隻是「中文（English）」，Goblin Alchemist、Human Bandit 是英文
5. 點開「人類骷髏（Human Skeleton）」：角色卡名稱是中文，內文、物品（彎刀、鏈甲衫）維持英文，數值正常。
6. 把「狼（Wolf）」拖到場景上，看 token 名稱有沒有中文。
7. 合集包瀏覽器（生物）用「以英文原名搜尋」打 `Stirge`，應該找得到「蚊蝠」。
8. 其他合集包（法術、專長）隨便點一條，確認沒有被影響。

要給簡體版：把 `_build/審核/zhcn/pf1.basic-monsters.json` 複製到 pf1e-compendium-zhcn 的 `translations/`，簡體 Foundry 照上面的步驟再測一次（合集包標題應該是「基础怪物」）。
