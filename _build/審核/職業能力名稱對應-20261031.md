# 職業能力名稱對應（2026-10-31）

合集包 `pf1.class-abilities` 的 4,352 條職業能力，逐條找出它在 AoN 上叫什麼、在哪一頁。
對照表在同資料夾的 `職業能力名稱對應-20261031.tsv`（一列一條，用 Excel 開），產生它的程式是 `_build/class_ability_names.py`。

**這次只做名稱對應，沒有動任何譯文。** `translations/` 一個字都沒改。對照表裡的「CHM 夾註」欄是 CHM 原文裡「中文（English）」的寫法，只給人核對，沒有填進合集包。

## 一句話結論

- 4,352 條裡，**3,924 條高信心、95 條中信心**對到 AoN；另有 98 條是「共用」（一條 Foundry 能力，AoN 在好幾頁各列一次，各頁都對）
- 56 條同名的不只一條、分不出來，沒挑；179 條還對不到
- 對到的裡面，**1,926 條在 CHM 該職業的頁面找得到同一個英文名的夾註**。其中 346 條是合集包現在還沒有中文名的（召喚師幻靈進化 79、操念使天賦 69、先知 41、牧師領域 28、異能者 26 最多）

## 資料來源（跟原本說的不一樣，先講清楚）

**「AoN 對不到 799 條」對不上這次的數字。** 那 799 條是 idmap 報告裡「FVTT 有、AoN 對不到」的 class-abilities 清單，idmap 的 AoN 端還吃了用語集（`pf1-glossary`），用語集這次拿不到，所以沒辦法重現那 799 條。
這次改成把合集包裡**全部 4,352 條**都跑一遍，另外用同一套 idmap 規則（`pf1.py` 的 `_pack_match()`）對這次重抓的職業選項索引算一次，標在對照表「現行規則」欄：照現行規則對不到的有 2,514 條（比 799 多，因為這次的 AoN 名冊沒有用語集那一份）。這 2,514 條裡，新規則對上 2,146 條高信心、87 條中信心、72 條共用。

## 轉換規則（照套用順序，第一條對得上就停）

每條後面的條數是用這條規則對上、而且是高或中信心的條數。

1. **原樣**：只差大小寫、撇號（’／'）、連字號、結尾的 (Ex)/(Su)/(Sp) 與 AoN 自己加的 `*`，就當同名。3,073 條
2. **去掉職業縮寫**：`Evasion (NIN)` → `Evasion`，而且只認忍者頁上的那條。縮寫表寫死在程式開頭（UMK＝掉鏈子武僧、SPI＝喚魂師……），不從字首猜。285 條
3. **去掉 (UC)**：`Ki Pool (UC)` → `Ki Pool`，只認掉鏈子職業的那條。52 條
4. **去掉進化點數**：`Bleed (1 pt)` → `Bleed`，只認幻靈進化。78 條
5. **去掉括號裡的家族名**：`Restriction (Stare)` → `Restriction`，只認凝視。19 條
6. **倒裝**：`Animal Fury, Greater` ↔ `Greater Animal Fury`。1 條
7. **去掉結尾的家族字**：`Efreeti Bloodline` → `Efreeti`（血統）、`Force Hook Infusion` → `Force Hook`（注能）、`Flight Hex` → `Flight`（巫術）、`Plague Patron`、`Truth Inquisition`、`Abjuration Resonant School` 同理。363 條
8. **子學派**：Foundry 寫 `Foresight Subschool`，AoN 寫 `Foresight School`。18 條
9. **炸彈**：Foundry `Anarchic Bomb`，AoN `Anarchic Bombs`。1 條
10. **上層＋通用能力名**：`Battle Final Revelation` → 秘示域 Battle 的 `Final Revelation`；`Frost Spirit Manifestation` → 魂域 Frost 的 `Manifestation`。48 條
11. **縮寫後再接上層**：`Resiliency (ORA) (Battle)` → 先知、秘示域 Battle 的 `Resiliency`。2 條
12. **拆開「上層：能力」**：`Wildfire Blessing: Fiery Wake` → 祝福 Wildfire 底下的 `Fiery Wake`。79 條

名字對上之後，**一律再核職業**：Foundry 條目有標所屬職業（pf1-data 的 associations），或名稱帶縮寫，就只收 AoN 上同職業的那條；職業不同的不收，在備註寫「AoN 有，但職業不同」。

同名不只一條時，用 Foundry 看得到的線索收窄，收不窄就不挑：
- 名稱帶 (UC) 的留掉鏈子版；沒帶、而且所屬職業有原版職業的，留原版
- Foundry 標籤寫了上層（`Battle Mystery`）的，留那個上層底下的
- Foundry 標籤寫了家族（`Alchemist Discovery`）的，留同家族的；沒有標籤的（職業本身的能力）留職業頁那條。例：`Mutagen` 沒標籤，對到鍊金術師職業頁的突變劑，不是同名的發現

## CHM：哪些職業頁找得到對應段落

方法：在 CHM 目錄「按類別／職業」底下的每一頁，找「中文（English）」夾註（CHM 的寫法是 `清心（Distraction, Su）`），英文跟轉換後的 AoN 名稱一樣才算。只當「這頁有這條」的線索：
- **沒有錨點**：CHM 還沒替職業能力插條目錨點，這裡沒有、也不該硬接成 `build_chm.py` 的新 KINDS
- **夾註會黏句子**：「它們被稱為幻靈」「根據操念使的元素念力」這種，中文欄要人看
- **職業變體頁也算進去**：同名的變體能力不一定是本體那條。對照表的「CHM 頁」欄可以看出是不是變體頁

## 對照表欄位

| 欄 | 內容 |
|---|---|
| Foundry 名 | 合集包譯文的鍵（Babele 比對用的英文原名） |
| 轉換後名 | AoN 上的名稱；共用／多筆用「｜」隔開全列 |
| AoN 頁 | AoN 網址（`https://www.aonprd.com/` 後面那段），就是這次說的 AoN id。職業能力在 AoN 多半沒有自己的頁，是寫在職業頁或選項頁裡，所以同一頁會對到很多條 |
| AoN 家族 | AoN 的分類；括號是上層（哪個血統、秘示域、領域） |
| 規則 | 用了上面哪一條轉換規則 |
| 信心 | 高／中／共用／多筆／— |
| 現行規則 | idmap 現在的比對規則對不對得到（對得到＝這條本來就沒問題） |
| CHM、CHM 頁、CHM 夾註（參考，未接） | 見上節 |
| 現有名稱 | 合集包現在的名稱（有中文才列） |
| 備註 | 收窄時排除了什麼、對不到的原因、最像的 AoN 名稱 |

## 怎麼重跑

程式只讀不寫合集包。路徑都是環境變數優先、沒設就用你電腦上原本的位置：

```
python _build/class_ability_names.py fetch   # 補抓缺的 AoN 頁（有快取就跳過，1 秒一頁；第一次約 400 頁）
python _build/class_ability_names.py         # 產對照表，零請求，約 20 秒
```

| 環境變數 | 預設 | 是什麼 |
|---|---|---|
| `PF1_TOOLS` | `C:\Users\User\Tools\pf1` | pf1.py 所在 |
| `PF1_INDEX` | `%PF1_TOOLS%\pf1-index` | 要先有 `aon-class-options.json`（`python pf1.py build --classopts-only`）；fetch 會把頁面存在底下的 `class-pages\`、`classopt-pages\` |
| `PF1_DATA_PACKS` | `%PF1_TOOLS%\pf1-data\packs` | Foundry 原始資料 |
| `PF1_CHM` | `D:\TRPG\4_工具與筆記\CHM勘誤` | 讀 `chmbuild\` 與 `toc.hhc` |

順便把 `build_chm.py`、`build_compendium.py`、`verify_compendium.py`、`glossary_names.py` 裡寫死的路徑也改成同樣的做法（`PF1_CHM`、`PF1_IDMAP`、`PF1_DATA_PACKS`、`FOUNDRY_DATA`、`PF1_ZHTW_BUILD`、`PF1_GLOSSARY`），預設值沒變，你在自己電腦上照舊跑不受影響。

## 要你決定的

1. 「拼法差一點」那 70 條要不要逐條確認後收進例外表（Foundry 打錯的也可以回報給 pf1 系統）
2. 元素變體（`Elemental Movement (Earth)` 這類四條一組）要對到 AoN 那一條，還是維持不對
3. CHM 線加職業能力錨點時，從上面那張「還沒中文名、CHM 有」的頁開始，合集包這邊換一次收穫最大
